# Domain docs

The engineering skills use a single-context layout for this repo.

## Before exploring

- Read `CONTEXT.md` at the repo root for project terms and domain rules.
- Read relevant ADRs in `docs/adr/` before working in an area they cover.
- If these files do not exist yet, proceed without them. Create them when the project resolves terms or decisions that belong there.

## Layout

- `CONTEXT.md`: the repo-wide domain context and glossary.
- `docs/adr/`: architecture decision records.

## Use the project's terms

Use the terms defined in `CONTEXT.md` in issue titles, proposals, hypotheses, and tests. If a needed term is missing, check the project's existing language before introducing one; record a genuine gap for domain modeling.

## Flag ADR conflicts

If a proposed change contradicts an existing ADR, identify that conflict explicitly before proceeding.
